# Nested probe V3
Independent, minimal Objective-C/UIKit guest. This is a control experiment, not a full BloomBox build. No LiveContainer or SwiftUI frameworks, extensions, signing account code or App Group access. Logs to stderr immediately at main and to Documents/BloomBoxDevProbeV3.log once a conventional guest HOME has been validated. If storage is unavailable, still attempt UI and display the reason. Counter is stored using a fresh temporary file and atomic rename. Install as a separate private guest, without extra tweaks, and compare its launch with V2. If it works, it proves a minimal UIKit executable can start in the host, not that nested BloomBox works. Next step is to reintroduce BloomBox components selectively. No merge or release.
